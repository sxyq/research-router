# 交互模式

只保留两种模式。判断 interaction 之前先提取 requirement model，不先按 scene 反推用户对象：

## `direct`

用户要求直接开始，或已经提供了 target 和 goal，且缺失信息不会改变主要 route。不要为了形式重复询问；按当前条件执行，缺口在结果中标记。

## `clarify`

用户要求先沟通，或缺少一个会改变主要 route 的条件。一次只问一个问题，优先顺序是：目标对象 → 主要问题 → 平台范围 → 证据深度 → 输出形式。每次回答后更新 requirement model，直到可以生成稳定查询词和验收条件。

不要把“是否放行”扩展成第三种防御流程；模式确定后直接进入场景判断和深度判断。
