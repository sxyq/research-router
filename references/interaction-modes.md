# 交互模式

只保留两种模式。判断 interaction 之前先由 Agent 理解当前请求和直接相关的对话上下文，再构建 requirement model；不先按 scene 反推用户对象：

## `direct`

用户要求直接开始，或上下文已经提供了可用的 target 和 goal，且缺失信息不会改变主要 route。先解析“这个”“它”等指代；不要为了形式重复询问，缺口在结果中标记。

## `clarify`

用户要求先沟通，或当前请求与上下文仍缺少一个会改变主要 route 的条件。一次只问一个问题，优先顺序是：目标对象 → 主要问题 → 平台范围 → 证据深度 → 输出形式。每次回答后由 Agent 更新 requirement model，直到可以生成稳定查询词和输出条件。

不要把“是否放行”扩展成第三种防御流程；模式确定后直接进入场景判断和深度判断。
