# 查询深度

深度由查询词数量、证据要求和并行程度共同决定；平台数量由用户需求决定。

| 深度 | 默认查询词 | 执行方式 | 结果要求 |
| --- | ---: | --- | --- |
| `light` | 2–4 组 | 一个 Agent 可使用一个综合 Skill；只补明确缺口 | 快速发现、少量链接和简短判断 |
| `medium` | 5–10 组 | 一个平台一个 Agent；同平台 Skill 按序执行 | 多组需求表达、交叉平台结果和关键原始页面 |
| `deep` | 11 组以上，或用户明确要求源码/PDF/完整证据 | 多个平台 Agent 并行；一个 Agent 负责一个平台并依次执行该平台命中的多个 Skill | 去重、冲突说明、源码或全文证据和统一结论 |

## 覆盖数量

不要用“查几个平台”决定深度。浅度可以查多个用户指定平台，深度也可以只查一个平台；区别在于查询词、证据和执行并行度。

## 默认组合

- `light`: 优先 `autocli` 这类综合 Skill。
- `medium`: 每个平台选择排序最高的主 Skill；只有明确缺口才追加第二个 Skill。
- `deep`: 运行全部命中的适用 Skill，但同一平台最多保留两个专项 Skill；综合 Skill 和最近时段 Skill 不计入该专项上限。

## GitHub 与学术提升规则

- 只要用户要求“源码、实现、依赖、测试、Issue、提交、Release”，GitHub 路由至少为 `medium`。
- 只要用户要求“论文是否支持这个结论、原文证据、引用核验”，学术路由至少为 `deep`。

## 公开论坛提升规则

- `light` 只读取论坛 RSS、版块列表或热门导读，适合快速发现。
- `medium` 读取发现结果对应的公开帖子正文，确认版本、步骤和上下文。
- `deep` 在需要时继续读取帖子多页回帖，并把论坛经验与 GitHub、官方资料或本地测量分开呈现。
